# フロントエンド高速化レポート：プリフェッチと Loading UI の導入

## 概要
ユーザー体験（UX）向上のため、Next.js App Router の機能を活用し、ページ遷移の高速化と視覚的な応答性の改善を行いました。

## 実施した内容

### 1. 積極的なプリフェッチの導入
主要なカード型UI（グループ一覧、プロジェクト一覧）の `Link` コンポーネントに `prefetch={true}` を追加しました。

*   **効果**: ユーザーがカードをクリックする前に、バックグラウンドで遷移先のデータの準備を開始します。
*   **対象**: 
    *   `app/(auth)/groups/page.tsx`（グループカード）
    *   `components/project/MyProjectList.tsx`（プロジェクトカード）

### 2. スケルトンUI（Loading UI）の実装
詳細ページへの遷移時に表示される `loading.tsx` を新規作成しました。

*   **効果**: データ取得中もレイアウトを維持したスケルトン（骨組み）を即座に表示し、ユーザーに「動作している」安心感を与えます。
*   **実装場所**:
    *   `app/(auth)/groups/[id]/loading.tsx`
    *   `app/(auth)/projects/[id]/loading.tsx`
*   **コンポーネント**: `components/ui/skeleton.tsx` を新設。

## 技術的トレードオフ

| 項目 | メリット | トレードオフ / 注意点 |
| :--- | :--- | :--- |
| **UX / 応答性** | クリックした瞬間に画面が反応し、体感速度が大幅に向上する。 | 特になし。 |
| **通信量 (Data)** | 遷移がスムーズになる。 | 画面内のリンク先のデータを事前に取得するため、ユーザーがクリックしなかった場合でも少量の通信が発生する。 |
| **サーバー負荷** | データを先読みできる。 | 一覧表示時にリンクの数だけリクエストが発生する。※現在の規模では問題なし。 |

## 今後の展望
リストが非常に長くなった場合は、`prefetch={true}` による全件取得ではなく、`Intersection Observer` を用いた動的なプリフェッチや、ホバー時のみ `router.prefetch()` を実行する手法への切り替えを検討してください。
